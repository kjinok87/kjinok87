## Selected Work

### PMO Review Report

산출물의 판본과 검토 기준을 확인한 뒤 발견 사항, 원문 위치, 업무에 미치는 영향, 보완 요청을 보고서에 담습니다. 예를 들어 통합시험 결과서에서 한 요구사항에 대응하는 시험 결과를 찾을 수 없다면, 검토 범위와 해당 위치를 남겨 구축사가 보완 후 같은 항목을 다시 확인할 수 있게 합니다.

### Skill RTM

요구사항 추적표(RTM)에 완료 기준, 구현 위치, 실행 근거를 연결합니다. 기능이 구현됐어도 시험 결과가 없으면 추가 검증 항목으로 남깁니다. 남은 작업에는 사용 조건과 검증 이력을 확인한 AI 스킬을 추천합니다.

### 오늘이 (Oneuli)

개발 목표와 완료 기준을 합의하고 한 번에 확인할 수 있는 기능 범위를 정하는 비공개 Codex 스킬입니다. 예를 들어 신청서 작성 기능을 만들 때 입력, 저장, 다시 열기까지를 한 단위로 정하고, 승인받은 범위와 실행 결과를 같은 요구사항에 연결합니다.

### Check the Brief

원래 요청을 항목별로 나누고, 각 항목의 식별자로 결과물과 근거를 대조합니다. 예를 들어 검토 의견마다 원문 위치를 적어 달라는 요청이라면 위치가 없는 의견을 찾아 표시하고, 필요한 부분을 수정한 뒤 같은 항목으로 재검수합니다.

### User Acceptance Interview

구현과 시험 기록에서 직접 확인할 흐름을 골라 시작 화면, 조작 순서, 기대 결과를 안내합니다. 예를 들어 저장한 값을 다시 열었을 때 그대로 보이는지 사용자가 확인하고, 차이가 있으면 결함과 수정 후 확인 결과를 연결해 기록합니다.
